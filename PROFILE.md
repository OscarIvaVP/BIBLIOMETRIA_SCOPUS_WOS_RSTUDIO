# 🚀 Introducción al Flujo de Trabajo en GitHub

Este repositorio ha sido creado como una guía práctica y visual para entender el ciclo de vida de un proyecto en GitHub, desde la creación de una rama hasta la integración final en la rama principal (`main`).

## 🎯 Objetivo del Proyecto
Demostrar de manera sencilla cómo colaboran los equipos de desarrollo utilizando las mejores prácticas de la industria, garantizando la calidad del código y la trazabilidad de los cambios.

## 🔄 ¿Cómo funciona nuestro flujo de trabajo? (Feature Branch Workflow)

El proceso que seguimos se compone de los siguientes pasos clave:

1. **Creación de la rama (`feature`):** Nos desviamos de la rama principal (`main`) para trabajar en una nueva funcionalidad o corrección sin afectar el código estable.
2. **Commits:** Realizamos cambios y los guardamos con mensajes claros y descriptivos.
3. **Pull Request (PR):** Solicitamos la integración de nuestros cambios. Aquí es donde el equipo **revisa y aprueba** el código. No es solo un paso técnico, es una barrera de calidad.
4. **Nuevos Commits:** Si la revisión requiere ajustes, subimos nuevos commits. El Pull Request se actualiza automáticamente.
5. **Merge:** Una vez aprobado, el botón de *Merge* fusiona nuestros cambios de forma segura en la rama `main`.

> **💡 Nota importante:** Técnicamente, un merge se puede hacer por terminal, pero en nuestro flujo el **Pull Request es obligatorio** porque la rama `main` está protegida para evitar errores humanos.

## 🛠️ Conceptos Clave
*   **Issues:** Registro de tareas, incidencias o ideas pendientes.
*   **Branch:** Línea de desarrollo independiente.
*   **Pull Request:** Solicitud de revisión y fusión de código.
*   **Merge:** La acción de integrar los cambios aprobados.
